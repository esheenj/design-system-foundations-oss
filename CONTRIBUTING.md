# Contributing to Design System Foundations

Thanks for helping improve this small, offline JavaScript reference project.

## Getting started

1. Read [README.md](README.md) for the project scope and API.
2. Use Node.js 20 or newer.
3. Run `npm test` and `npm run demo` before making changes.
4. Keep changes focused; include tests for changed logic or validation.
5. Open a pull request describing the problem, design decision, and verification.

## Useful contributions

- Reproducible bug reports for alias resolution, cycle detection, or input validation.
- Tests for documented edge cases and deterministic CSS output.
- Clearer examples or accessibility explanations with appropriately limited claims.
- Documentation on using the exported functions in an existing app.

For larger behavior changes, discuss the intended API and supported value types in an issue first.

## Pull request checklist

- [ ] Scope is explained and consistent with the README.
- [ ] `npm test` passes, or a failing check is clearly explained.
- [ ] `npm run demo` still works if relevant.
- [ ] Tests and documentation are updated for changed behavior.
- [ ] No secrets, private code, customer information, or third-party assets without permission.
- [ ] No unsupported claims of accessibility compliance or certification.

## Privacy and responsible reporting

This repository is deliberately public. Do not paste private tokens, API keys, production access details, or personal data into issues or pull requests. For a suspected security vulnerability, avoid posting exploitation details publicly; contact the maintainer privately using an available contact channel instead.

## AI-assisted contributions

AI-assisted work is welcome when contributors review its accuracy, run relevant tests, and disclose meaningful generated changes as appropriate. Do not assume an automated test run proves security or accessibility conformance.
