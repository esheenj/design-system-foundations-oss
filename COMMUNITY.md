# Community feedback and contributions

This is a small **offline, dependency-free reference implementation**, not a hosted service, full design system or accessibility certification.

## Help shape the project

We especially welcome:
- Real use cases for token aliasing and validation, described with synthetic examples.
- API usability feedback from people integrating it into vanilla JS or a design-system workflow.
- Reproducible tests for currently documented behavior.
- Documentation edits that make the project more useful to beginners.
- Reviews of the limits of simplified numeric contrast calculation, without compliance claims.

Please use the [issue tracker](https://github.com/esheenj/design-system-foundations-oss/issues) for bug reports or feature proposals. Use a focused PR for changes that can be tested locally. See [CONTRIBUTING.md](CONTRIBUTING.md) and [AGENTS.md](AGENTS.md).

## Feedback questions

1. Which feature would help you put this compiler to use in an actual project?
2. What is the smallest token object that currently fails your use case?
3. Would CLI JSON input, CSS variable output, additional value types or a TypeScript declaration improve adoption?
4. What should remain intentionally out of scope?

The maintainer will prioritize open contributions by utility, clear tests, maintenance cost and scope. Public issue discussions are visible to everyone: **never share secrets, internal client source or real user data**.

No contribution or feature request grants access to internal Esheen Labs repositories, private roadmaps, customers or commercial decision logic.
